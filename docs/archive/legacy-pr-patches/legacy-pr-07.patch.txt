+### Design and identity boundaries
+
+- No Auth0, melody-auth, or legacy Breezze OAuth pairing endpoint is used by the active login UI. The old controllers are not registered in NestJS.
+- The Flutter client sends the **Supabase access token** to the Breezze API, which verifies the user and maps the Supabase user ID to the app's Prisma user row.
+- An existing Breezze account using the same email but a different user UUID is **not silently merged**, to avoid account takeovers. Migration requires a separate verified account-linking flow.
+- Backend admin MFA actions are fail-closed until a verified Supabase AAL2-to-admin authorization design is implemented.
+- Old password confirmation for account deletion is not applicable to Google/Apple accounts. The account screen directs users to Support pending a secure identity-verified deletion path.
+- Breezze's API, playlists, favorites, and playback permissions remain on the NestJS side. The Supabase `public` schema does not need to duplicate the Prisma tables merely to enable Auth.
+
+## Verification checklist
+
+- Email registration creates an identity in Supabase Auth, shows an email-confirmation state when required, and returns to Breezze after confirmation.
+- Email sign-in/sign-out and persisted session restore work on a fresh Android emulator and iOS simulator.
+- Android Google native credential sheet returns a valid Google ID token, then a Supabase session; iOS Google uses the correct URL scheme and client IDs.
+- Native Apple Sign-In returns an ID token and Supabase session, including a nonce challenge; the first available full name is saved in profile metadata.
+- An invalid/tampered/expired token is rejected by NestJS. Two users cannot see one another's account-owned library/playlist data.
+- A signed-out client receives 401 for account endpoints. A valid Supabase bearer token passes the NestJS guard and creates/loads a matching Breezze Prisma user.
+- Signing out of all devices invalidates Supabase refresh tokens; servers should never treat a cached token as proof of a current session.
+- CI builds Android, iOS, web, macOS, Linux and Windows where supported. Manual provider checks require real OAuth credentials and signed app targets.
+
+**Status:** Code and public Google client defaults prepared in `feat/supabase-auth-breezze`. Google provider is enabled with its Web + iOS client IDs and a saved, masked OAuth client secret. Google OAuth and Android native login are not fully verified; Apple requires developer membership; auth PR is not yet merged or deployed. Backend deployment and end-to-end device tests remain before launch.

+# Breezze Master Plan v3 — implementation baseline
+
+**Status:** Adopted as the target architecture, not a claim that all eleven phases are complete. The existing Flutter + NestJS + Prisma deployment remains supported until each replacement passes its acceptance gate. Never remove the old data source or deploy incompatible clients/backend independently.
+
+## 1. Product contract
+
+- Listener-first, free to use, no subscriptions, billing, ads, radio tab, or social graph.
+- Primary navigation: **Home · Browse · Library · Search**, persistent global mini-player and Now Playing.
+- Custom, on-brand Flutter authentication UI, styled with Breezze's existing design tokens and SVG icons; OS-managed Google/Apple consent remains native.
+- Supported build targets: Android, iOS, web, Windows, macOS, Linux (verify runtime behavior per platform; platform packaging and background audio are not uniform).
+- Metadata discovery is not permission to stream, cache, rip, or download third-party recordings. All playback, DRM, region restrictions, provider authentication and offline rights are validated server-side.
+
+## 2. Target topology and migration seam
+
+```text
+ Flutter (Riverpod + custom Supabase Auth UI + shared player)
+   |  \-- Supabase Auth (GoTrue) / Postgres, with RLS for personal data
+   |  \-- Supabase Edge Functions (thin, user-JWT-verified orchestration)
+   |        |-- YouTube Music discovery: metadata only (Python)
+   |        |-- Deezer: rights-authorized playback only (Node)
+   |        |-- Lyrics (LRCLIB, subject to its terms)
+   |        \-- cache with authenticated tenant-aware keys + expiry
+   \----- Current NestJS / Prisma API (migration compatibility and rights guard)
+                 \-- existing user libraries/catalog/queue endpoints
+```
+
+The **Flutter client must never receive provider account credentials**, server-side ARL tokens, Supabase service-role/secret keys, or decrypted credential records. Authentication and authorization are separate: a valid session does not imply entitlement to a stream.
+
+**Rollout rule:** Supabase is the source of identity now, and `public.profiles` becomes the source of user profile display data. Existing canonical tracks, favorites, playlists and listening history remain in Prisma until data migrations, parallel-run comparisons, signed-off access tests and reversible cutover. No automatic UUID/email merging of pre-existing accounts.
+
+**Supabase Edge Functions:** initially limited to stateless, low-latency orchestration; do not move every NestJS route immediately. Resolve per-request user access tokens and rights on the server, never proxy unlicensed streams. The function can call specialist services through authenticated, private service APIs. `EdgeRuntime.waitUntil` is bounded background execution, **not an unlimited long-running job runner**; heavy exports belong in a dedicated worker or queue. Cron (pg_cron/pg_net) is an optional scheduled trigger, with limits and idempotency.
+
+## 3. Auth — one Supabase identity authority
+
+- Flutter: `supabase_flutter`; Google with `google_sign_in` 7.x; Apple with `sign_in_with_apple`.
+- Google: obtain the Google ID token and, via `GoogleSignInAccount.authorizationClient`, the access token for basic identity scopes, then call `signInWithIdToken(provider: google, idToken:, accessToken:)`. Native Android needs a matching OAuth signing SHA-1. Current Breezze web and iOS clients are configured in Google Cloud/Supabase; client secret is configured in Supabase.
+- Apple: native `signInWithIdToken(provider: apple, idToken:, nonce: rawNonce)` with a SHA-256-hashed nonce sent to Apple. Apple Developer Program membership **not active**; keep integration code but leave the Apple provider unlaunched until app identifiers, entitlements and credentials can be created. Web/other platforms use configured Apple OAuth only after its Service ID and signing key are active. Apple private .p8 keys should be protected; it is the **signed client-secret JWT** that expires and needs renewal (typically no more than six months), not an automatic six-month rotation of the private .p8 file.
+- Email/password: fully custom Breezze widgets; email verification, password reset + deep-link callback and deletion are acceptance requirements.
+- Signed-out guest browsing: local device-scoped state, no pretend server authority or `auth.uid()`. Guest data is not synced as another user's account. Upgrade to an account via explicit migration of locally-owned data.
+- Subscribe to `onAuthStateChange` **with `onError`**. Supabase owns refresh and sessions. Native sessions use an explicit `flutter_secure_storage` `LocalStorage` adapter; web uses the SDK's browser persistence. Avoid persisting raw tokens in extra stores or logs.
+- Apply strict per-user access checks in every Prisma endpoint during migration. Never trust client-supplied `user_id` or user-editable `user_metadata` as authorization proof.
+- Preserve BREEZZE styling, not a hosted Supabase login UI.
+- Apple pending activation **must not block Google or email tests**.
+
+## 4. First deployed Supabase data layer: profiles
+
+`public.profiles` now exists in the connected Breezze Supabase project. It is keyed by `auth.users.id`, has own-row-only `SELECT/INSERT/UPDATE` policies, enables RLS, blocks Supabase anonymous identities, and contains `display_name, handle, avatar_url, country, created_at, updated_at`. An isolated private trigger creates profiles on new Auth signups; there is a backfill for existing Auth users. The SQL in `docs/database/BREEZZE_V3_PROFILES_RLS.sql` is the reproducible baseline.
+
+**Verified:** table and FK exist; RLS on; Supabase security advisor: 0 findings; performance advisor: 0 findings. No Supabase Auth users were present at the time of the check, so a real signed-in profile insert/read/write isolation test is still a gate.
+
+Planned follow-on tables, **not yet deployed**:
+- `public.user_library`: user-scoped track keys, saved timestamps, unique `(user_id, track_id)`; RLS on all reads/writes; indexed `user_id`.
+- `public.pinned_playlists`: `(user_id, playlist_id, position)`, owner-only RLS, indexed by owner.
+- `public.connected_providers`: metadata only (provider name/status). **Never expose provider credentials or decrypted secrets in public tables**, even with RLS. Put server-managed encrypted credentials in an unexposed private schema or secrets manager, with tightly scoped server-only access.
+- Canonical catalog / playlists / history: create a specific one-way + backfill + reconciliation + rollback migration contract per table before re-pointing Flutter away from Prisma.
+
+All owner policies must include `TO authenticated`, `USING (auth.uid() = owner)`, and for writes `WITH CHECK`. Ensure `anon` cannot read profiles; server-verified authorization remains mandatory for playback.
+
+## 5. Flutter and media
+
+| Domain | v3 target | Release condition |
+| --- | --- | --- |
+| UI shell | existing Riverpod + go_router + design system | four tabs, mini-player survives navigation |
+| Standard audio | just_audio + audio_service + audio_session | queue, gapless, interruption recovery, lock-screen and route tests |

+| Search intelligence | stage `flutter_edge_ai` / EmbeddingGemma 2 | text-only 270M pilot first; cap RAM/download; user-opt-in model download; switch to 740M multimodal only after mobile benchmark |
+| Lyrics | LRCLIB under provider terms | valid synchronized timecodes, fallbacks, accessibility |
+
+Do **not** feed a streaming URL into multiple independent audio players simultaneously: a single authoritative playback state/queue must own controls. Feature-flag DSP engines until crossfade and background media sessions are verified. Spatial DSP is **not Dolby Atmos** certification, and lossless playback is dependent on source format, license and output path.
+
+Semantic search only covers embeddings actually derived for the user's **local authorized library**. Text-based metadata embeddings cannot masquerade as full audio-similarity search. Do not bundle the 740M model with every install; gate it by opt-in, supported devices, disk/battery/network budget and real benchmarks. Cache vectors locally with model version and invalidate on model upgrades.
+
+## 6. Acceptance gates / phase order
+
+1. **Identity foundation:** Google + custom email functional on emulator and web, Supabase session restore + refresh, failed-token paths, RLS tests, no cross-user leaks. Apple held pending enrollment.
+2. **Profiles and account:** link profile UI to Supabase `public.profiles`; account reset, support and deletion flows; save/edit/reopen profile.
+3. **Backend transition:** staged migration from Prisma to Supabase with checksums and rollback; Edge Function resolver behind a feature flag; provider eligibility tested.
+4. **Catalog UI:** real Home, Browse, Library and Search content, no radio; artist/album/playlists; mini-player persists.
+5. **Playback:** ten-track queue, focus/interruptions/reconnect, compatible licensed downloads and airplane-mode playback.
+6. **Audio DSP:** chosen single DSP integration, ten-minute glitch-free stress test on low-end Android; no advertising of unsupported formats.
+7. **Video:** bounded `media_kit` player pool, 20-item scroll, OS decoder and memory test.
+8. **AI search:** benchmark 270M on low-tier device, opt-in, local vectors, measurable search relevance and memory cap.
+9. **Settings:** all eleven sections bound to Riverpod + persisted preferences; dark/light themes, accessibility.
+10. **Operational readiness:** CI all platforms, staging smoke, privacy/security review, logs/metrics, rate limits, account data export/deletion, rollback.
+11. **Release readiness:** device/emulator test matrix, licensing checks, support and app-store requirements; independent sign-off for each platform.
+
+**Current status:** Profile schema live and audited. Flutter auth code and custom UI live only in draft PR #7; Google dashboard provider configured but no end-to-end auth device proof or production release; Apple awaiting membership. The advanced engine, video pool, on-device AI and Supabase Edge orchestration are **planned**, not implemented.
+
+## 7. Non-negotiable guardrails
+
+- No copyrighted stream extraction, bypass of Deezer entitlements, unauthorized ARL reuse, or fake offline rights.
+- Never merge a Supabase Auth user onto an existing Breezze account solely by email.
+- A valid Supabase JWT does not replace RLS, explicit per-owner checks or playback authorization.
+- Keep Redis keys user- and rights-context-aware where necessary; provider URLs have short validity and must not be globally reissued.
+- Never publish or commit Google OAuth secrets, Apple .p8 keys, Supabase service-role keys or per-user provider credentials.
+- Performance claims are measured per supported device and platform; no unverified <200ms playback assertion.
+- Coordinate mobile backend changes, staged rollouts, monitoring, support and rollback, then merge PR only after all required checks.

+# BREEZZE MASTER PLAN v3 — execution contract
+
+**Status:** Adopted target architecture. This document complements the original v3 specification without claiming unimplemented work is complete. Preserve Breezze's premium, restrained Apple Music-inspired visual system, black/white brand mark, accessible SVG icons, and exactly four tabs: **Home, Browse, Library, Search**. Global mini-player and Now Playing remain shared. No radio, social graph, ads, subscriptions or billing screens. Android/iOS primary, with Windows/macOS/Linux/web targets evaluated by CI.
+
+## 1. Architecture and migration boundaries
+
+Target:
+
+```text
+Breezze Flutter (Supabase-authenticated)
+  ├─ Supabase Auth (Google first, Apple once Developer Program active, email/password)
+  ├─ Supabase Postgres with per-user RLS: profiles and owned library data
+  ├─ Supabase Edge Functions: short-lived gateway/orchestration, auth, prefetch
+  └─ Proven media services: metadata/discovery, authorized stream resolution, lyrics
+       ├─ YouTube Music metadata/discovery (unofficial ytmusicapi adapter)
+       ├─ rights-compliant Deezer / SoundCloud playback adapter when permitted
+       └─ LRCLIB with attribution
+```
+
+**Migration rule:** Current NestJS + Prisma/Cloudflare services remain operational until parity tests and a reversible cutover demonstrate that each Supabase successor works. Do not destroy Prisma-owned favorites, playlist records or catalog during the migration. No dual writes without idempotency, conflict resolution, per-user tenancy tests and a defined owner of each entity. Provider metadata is not a license to stream, download, or cache copyrighted audio; ARL tokens likewise do not grant universal playback rights.
+
+Domain ownership:
+- **Identity:** Supabase Auth is the sole identity/session authority; do not resurrect legacy NestJS JWT issuing or Auth0.
+- **User profile:** `public.profiles` (Supabase, user ID = `auth.users.id`), owned by user RLS; profile updates should eventually write directly to Supabase instead of NestJS. During transition, preserve any NestJS onboarding and territory rules.
+- **Personal library:** `public.user_library` and `public.pinned_playlists` are created as *additive migration targets*; legacy Prisma library/playlists remain live until synchronized and tested. Canonical IDs must map unambiguously across both databases.
+- **Catalog and rights:** existing metadata/canonical IDs and territory/rights records remain in current backend until provider resolution is replaced.
+- **Provider credentials:** **never** store third-party provider credentials in user-selectable `public.connected_providers` rows. Use server-only secret storage for service-level keys, or a private schema/service-controlled vault for explicitly authorized per-user secrets. Do not expose credentials to RLS-filtered client reads.
+- **Cache:** hot TTL cache (Redis/Upstash as supported), source-specific TTL, invalidation and provider rate limits. Keep audio bytes off Supabase functions.
+- **Observability:** structured latency, auth failure, playback-rights and resolution errors without logging tokens, private user data or stream URLs.
+
+## 2. Auth UX and lifecycle
+
+The custom Breezze Flutter authentication screen stays native to the app, with direct `supabase_flutter` calls; no branded hosted authentication screen. Native Google/Apple *provider authorization sheets* are still OS-owned. Keep the existing sign-in/register styling and accessible focus states; add Forgot Password, email-reset handling, first-run avatar/personal details and account deletion only when each backend path exists.
+
+Use Supabase `onAuthStateChange` for `initialSession`, `signedIn`, `signedOut`, `tokenRefreshed`, `userUpdated`, and `userDeleted`; always provide an `onError` listener, dispose subscriptions, and clear owner-specific in-memory caches on a user switch. Let the SDK manage refresh and persistence; **never log or mirror refresh tokens to Hive/Isar**. Native Google `signInWithIdToken` uses both the Google ID token and Google access token, per Supabase's current Flutter integration guidance. `google_sign_in` 7 exposes the access token through the account's `authorizationClient` (not the old `authentication.accessToken` API); limit authorization scopes to basic identity information. Apple ID-token sign-in should use secure nonce generation and hashing; **Apple stays pending** until Developer Program membership and native entitlements can be configured.
+
+**Mandatory sign-in:** only an authenticated Supabase user may access Home, Browse, Library, Search, or the player. Signed-out and expired-session states show the custom Breezze sign-in screen; there is no Browse bypass or anonymous-home mode. Historical device-only guest data is a separate migration concern and must never be attributed to another account. Password-reset callbacks and OAuth redirect allowlist must be configured before release.
+
+**Current implementation changes:** Follow/Unfollow is already in the backend and now stores the artist display name, lists followed artists in Library, and contributes to rights-filtered Home candidate generation; Home shows a separate followed-artist rail and a Made for You rail. Apple logo remains visible but the button is disabled until activation. User-selected language is stored in Supabase profiles plus per-user local secure storage, and the app starts in English.
+
+**Current auth status:** Supabase project `djwvyjtebmsavhcrmhxf`. Google web+iOS OAuth client IDs and web secret configured in Supabase, Google provider enabled; Android signing SHA-1/client remains outstanding; an actual end-to-end provider login still needs test. Apple Developer membership inactive and Apple native login is blocked. The supabase Flutter code lives in draft PR #7; the deployed API/client has **not** been switched to the PR.
+
+## 3. Supabase RLS foundation
+
+Existing: `public.profiles`, `id uuid` FK to `auth.users(id)` and owner-only `TO authenticated` SELECT/INSERT/UPDATE policies. Additional implemented migration: `breezze_v3_user_library_and_pins_rls` creates:
+
+- `public.user_library(id, user_id, track_id, added_at)` with FK, uniqueness on `(user_id, track_id)`, owner+timestamp index and owner-scoped SELECT/INSERT/UPDATE/DELETE.
+- `public.pinned_playlists(id, user_id, playlist_id, position)` with FK, uniqueness on `(user_id, playlist_id)`, owner+position index and owner-scoped SELECT/INSERT/UPDATE/DELETE.
+
+Every policy checks `(select auth.uid()) = user_id` (or `id`) and excludes `auth.jwt()->>'is_anonymous' = 'true'`. INSERT uses `WITH CHECK`; UPDATE uses both `USING` and `WITH CHECK`. RLS is enabled, public/anon table grants revoked, and access is limited to authenticated. Supabase Security Advisor reported **zero security lints** after schema creation; the initial RLS JWT initplan performance warnings were resolved by migration `breezze_v3_owner_rls_jwt_initplan` (only expected unused-index informational notices remain while tables are empty). **Not yet verified:** authenticated two-user CRUD negative tests with real sessions, frontend CRUD wiring, legacy guest-data import, or exposed Data API configuration.
+
+Keep RLS verification in CI: one real user can read/write only own rows; unauthenticated users see none; user A cannot select/insert/update/delete user B's rows; ownership fields cannot be reassigned. Include actual PostgREST tests or pgTAP tests when available. Database isolation never substitutes for checking authorization in provider resolver endpoints.
+
+## 4. Backend / Edge Functions
+
+Incrementally implement only low-latency, authorized orchestration as Supabase Edge Functions (Deno/TypeScript):
+- `POST /resolve`: Supabase caller identity, territory, catalogue source match, provider capabilities and rights grant, rate limiting, caching. A non-playable metadata hit must never be reported as a playable stream.
+- `POST /prefetch`: bounded list of next track IDs (max 3), identity/territory checks, no uncontrolled fan-out.
+- catalogue discovery aggregation and lyrics proxy as independent functions if benchmarks justify.
+- audit logs without bearer tokens or ARL secrets.
+
+Do not execute blocking Python ytmusicapi, native codecs, DSP or large media conversion *inside* Edge Functions; delegate to bounded services and respect Supabase hosted CPU/memory/wall-clock limits. `EdgeRuntime.waitUntil` is only for bounded background work, not guaranteed durable jobs; use queues/jobs with retries, idempotency and dead-letter handling for exports/recommendation batches. Cron is for safe metadata/cache maintenance, never automatic secret/session deletion without understanding the auth platform. Preserve existing Cloudflare and Railway deployments until new endpoint contracts are validated.
+
+## 5. Media and offline contract
+
+Baseline: `just_audio + audio_service + audio_session`, one consistent queue, lock-screen/Bluetooth controls, global Now Playing; physical/emulated device tests for interruption/recovery. Playback rights must be checked server-side per track, action and territory. Downloads must be disabled where licenses do not grant offline rights; never bypass provider DRM. Do not promise high-resolution/lossless when the source, hardware or output path cannot support it.
+
+Advanced DSP is **opt-in experimental**: benchmark `flutter_soloud` for custom realtime native filters or `sautiflow` for integrated high-fidelity crossfade/EQ. These engines overlap with `just_audio`; define exactly one playback owner rather than double-rendering audio. Native audio-thread code must be deterministic and nonblocking, avoid locks, allocation, I/O and Dart VM calls; communication uses bounded lock-free queues. Test low-end device CPU, thermal load, glitches, battery, and background audio before promotion.
+
+Video: validate `media_kit` using a bounded lazy player pool and LRU disposal; **3–5 is a benchmark target, not a proven universally safe decoder count**. Limits vary by hardware/codec. Scroll-test 20 videos with memory/decoder telemetry and foreground/background transitions.
+
+Lyrics: use attribution, licensing constraints and synced/unsynced fallbacks; avoid presenting a missing lyric as a failed playback.
+
+## 6. On-device semantic search
+
+Google's EmbeddingGemma 2 model is real: modular 270M text-only, 440M text+vision, 570M text+audio, 740M full multimodal, up to 768-dimensional embeddings. Treat integration via `flutter_edge_ai` or `semantic_search_codespark` as **unproven until an executable compatibility POC** on Flutter Android/iOS. No remote AI keys required for an offline implementation, but model weights, distribution rights, startup/RAM costs and device storage are real constraints. Use text-only semantic library search first, with deterministic keyword fallback and opt-in model download; later test locally available audio embeddings if legal and technically feasible. Benchmark cold start, battery, memory, retrieval quality and airplane mode. Never block basic library search waiting for a 740M model.
+
+## 7. UX and data contracts
+
+Keep the four-tab shell, shared mini-player, player hero transitions, app-wide on-brand color tokens and restrained motion; no duplicate Settings/Account pages; the required Supabase sign-in gate applies before opening any tab. Profile settings keep language, territory, genres and saved artists; one source of truth and a clear migration plan for existing user preferences are required. Every profile mutation must be validated, owner-isolated and retriable; display honest loading/empty/offline states.
+
+The 11 Settings sections should be connected to Riverpod persistence, with switches reflecting actual enabled capabilities—not decorative controls. **Login is required for every listener.** English is the initial app language, selectable in Settings; translated primary labels and native Material localization are in place for a subset of languages, while untranslated Breezze copy falls back to English. Existing designs are retained rather than replaced with an unrelated UI kit.
+

+# Breezze — Spotify-inspired discovery and personalization (research + implementation)
+
+Breezze's recommendation engine is independently designed, based on publicly described techniques and transparent user-control principles. It is **not** Spotify's proprietary model or a claim of model-level parity.
+
+## Research findings
+
+1. Spotify's publicly described Home architecture uses **two stages**: generating candidate tracks/artists/collections and ranking them into shelves. Recommenders must balance relevance with variety rather than merely sorting by plays. Source: [Spotify Engineering — Rise of ML Models on Home](https://www.engineering.atspotify.com/2021/11/the-rise-and-lessons-learned-of-ml-models-to-personalize-content-on-home-part-i).
+2. Spotify uses a **taste profile** that reflects interactions, follows, listening, favorites and recommendation feedback. Following an artist helps new-release discovery and recommendations. Sources: [Spotify — Understanding Recommendations](https://www.spotify.com/uk/safetyandprivacy/understanding-recommendations) and [Spotify Support — Following artists](https://support.spotify.com/us/article/follow-artists-podcasts-and-shows/).
+3. Separate **short-term and long-term interests** help balance recent moods and stable music taste; Spotify Research publicly describes 1-week, 1-month, and 6-month representations. Source: [Generalized User Representations (2025)](https://research.atspotify.com/2025/9/generalized-user-representations-for-large-scale-recommendations).
+4. Recommendation ranking should optimize durable user satisfaction, discovery, diversity, and artist fairness—not just clicks or repeated plays. Spotify published research on contextual-bandit calibration and cross-shelf balancing. Source: [Calibrated Recommendations (2025)](https://research.atspotify.com/2025/9/calibrated-recommendations-with-contextual-bandits-on-spotify-homepage).
+5. Flutter requires both translated strings and localization delegates to truly localize the UI; a language preference alone is **not full translation support**. Source: [Flutter internationalization](https://docs.flutter.dev/ui/internationalization).
+
+## Product rules (binding)
+
+- Breezze **requires login** to enter any of the four tabs, including Home. Google is configured and Apple stays visible but disabled while activation is pending. Custom Flutter auth UI only.
+- English (`en`) is the initial default. The Settings language selector exposes a broad catalog and stores the user's choice. Native Flutter controls can localize to supported locales. **Breezze-specific strings require reviewed translations**; do not market unsupported languages as fully translated.
+- Artist Follow and Unfollow use the real authenticated account's library API. Followed artists must appear in Library even when zero tracks are saved.
+- Following is a strong explicit recommendation signal. Unfollowing removes its *follow-specific* weight; previous legitimate listening/favorites may continue to affect recommendations.
+- Artist and track metadata are **not** media rights. Before publishing any full-track recommendation, the rights filter validates available full-stream rights for the trusted edge territory.
+- No purchase, subscription, ad, social feed, radio, fake streaming source, or hidden tracking.
+
+## What is implemented in the draft PR
+
+- Mandatory Supabase auth gate and disabled-but-visible Apple logo; removed unauthenticated Browse shortcut.
+- Language catalog, searchable Settings language picker, persisted per-account Supabase `profiles.language` plus local offline fallback, `MaterialApp.locale` and SDK localization delegates.
+- Prisma `UserFollowedArtist.artistName` migration and authenticated artist listing. Follow passes the artist's display name from the artist screen.
+- Library artists list includes followed entries independent of saved songs, with followed artists sorted first.
+- Recommendation candidate generation now uses followed canonical artist IDs and names, preferred/onboarding artist names, favorites, and **server-verified listening events**. Candidate tracks are ordered by album release date when available, artist-interleaved, and checked for territory-specific full-stream rights, with a two-tracks-per-artist diversity cap. Followed tracks get a reason of “Because you follow this artist”.
+- Home shelves separate “From Artists You Follow” from “Made for You”, followed by recently played and favorites, with no duplicate items between followed and personalized shelves.
+
+## Future improvement gates (NOT claimed implemented)
+
+- Provide full UI translation resources for each displayed locale and an English fallback audit, including RTL layouts and locale-specific search.
+- Add search impressions / skip / hide / thumbs-down events with **clear privacy controls**, opt-out, retention limits and authenticated owner isolation. Do not infer explicit dislikes from provider errors.
+- Build canonical genre/mood and artist similarity taxonomy for real cross-artist discovery; currently candidate recall primarily finds more songs from known/followed artists.
+- Create a verified Release Radar from actual release dates of followed artists and a Daily Mix with constrained diversity, then benchmark content freshness and rights clearance.
+- Train/rank from short (week), medium (month), and long-term listening patterns only after sufficient lawful activity data and an appropriate privacy model exist. Benchmark cold start, minority genres, creator coverage, and all-user fairness.
+- Validate real session/device testing, two-user row isolation, server playback grants, signed builds, and lifecycle reliability before enabling production routing.
+

+begin;
+
+create schema if not exists private;
+
+create table public.profiles (
+  id uuid primary key references auth.users(id) on delete cascade,
+  display_name text check (display_name is null or char_length(display_name) <= 80),
+  handle text unique check (handle is null or handle ~ '^[a-z0-9_]{3,24}$'),
+  avatar_url text,
+  country text check (country is null or country ~ '^[A-Z]{2}$'),
+  created_at timestamptz not null default now(),
+  updated_at timestamptz not null default now()
+);
+
+alter table public.profiles enable row level security;
+
+-- Supabase anonymous sessions use the authenticated PostgreSQL role;
+-- forbid such identities from accessing durable Breezze profile data.
+create policy "profiles_select_own" on public.profiles
+  for select to authenticated
+  using (
+    (select auth.uid()) = id
+    and ((select auth.jwt()) ->> 'is_anonymous') is distinct from 'true'
+  );
+
+create policy "profiles_insert_own" on public.profiles
+  for insert to authenticated
+  with check (
+    (select auth.uid()) = id
+    and ((select auth.jwt()) ->> 'is_anonymous') is distinct from 'true'
+  );
+
+create policy "profiles_update_own" on public.profiles
+  for update to authenticated
+  using (
+    (select auth.uid()) = id
+    and ((select auth.jwt()) ->> 'is_anonymous') is distinct from 'true'
+  )
+  with check (
+    (select auth.uid()) = id
+    and ((select auth.jwt()) ->> 'is_anonymous') is distinct from 'true'
+  );
+
+revoke all on public.profiles from anon;
+grant select, insert, update on public.profiles to authenticated;
+
+-- Trigger is SECURITY DEFINER because the Supabase Auth role must be able
+-- to create the corresponding public row. Keep function in a private,
+-- unexposed schema with a fixed search_path and no public EXECUTE grant.
+create function private.create_breezze_profile()
+returns trigger
+language plpgsql
+security definer
+set search_path = ''
+as $$
+begin
+  insert into public.profiles(id, display_name, avatar_url)
+  values (
+    new.id,
+    left(nullif(btrim(coalesce(new.raw_user_meta_data ->> 'full_name', new.raw_user_meta_data ->> 'name', '')), ''), 80),
+    nullif(new.raw_user_meta_data ->> 'avatar_url', '')
+  )
+  on conflict (id) do nothing;
+  return new;
+end;
+$$;
+
+revoke all on function private.create_breezze_profile() from public, anon, authenticated;
+
+create trigger on_breezze_auth_user_created
+after insert on auth.users
+for each row execute function private.create_breezze_profile();
+
+insert into public.profiles(id, display_name, avatar_url)
+select id,
+  left(nullif(btrim(coalesce(raw_user_meta_data ->> 'full_name', raw_user_meta_data ->> 'name', '')), ''), 80),
+  nullif(raw_user_meta_data ->> 'avatar_url', '')
+from auth.users
+on conflict (id) do nothing;
+

+import "jsr:@supabase/functions-js/edge-runtime.d.ts";
+
+// Metadata-only prefetch. NEVER return a provider media URL or imply rights.
+const apiOrigin = Deno.env.get("BREEZZE_API_URL")
+  ?? "https://breezze-api-edge.ykw8vmq7ph.workers.dev";
+const cors = {
+  "Access-Control-Allow-Origin": "*",
+  "Access-Control-Allow-Headers": "authorization,apikey,content-type,x-client-info",
+  "Access-Control-Allow-Methods": "POST, OPTIONS",
+  "Cache-Control": "no-store",
+};
+function json(payload: unknown, status = 200): Response {
+  return new Response(JSON.stringify(payload), {
+    status, headers: { ...cors, "Content-Type": "application/json" },
+  });
+}
+const allowed = /^bz:(youtube_music|deezer|soundcloud):([A-Za-z0-9_-]{1,128})$/;
+
+Deno.serve(async (request: Request) => {
+  if (request.method === "OPTIONS") return new Response(null, { status: 204, headers: cors });
+  if (request.method !== "POST") return json({ error: "METHOD_NOT_ALLOWED" }, 405);
+  if (Number(request.headers.get("content-length") || "0") > 4096) {
+    return json({ error: "PAYLOAD_TOO_LARGE" }, 413);
+  }
+  const authorization = request.headers.get("Authorization") ?? "";
+  if (!authorization.startsWith("Bearer ") || authorization.length > 8192) {
+    return json({ error: "UNAUTHENTICATED" }, 401);
+  }
+  const supabaseUrl = Deno.env.get("SUPABASE_URL");
+  const apiKey = Deno.env.get("SUPABASE_ANON_KEY");
+  if (!supabaseUrl || !apiKey) return json({ error: "AUTH_UNAVAILABLE" }, 503);
+
+  try {
+    // Verify the user server-side even if the gateway's JWT setting changes.
+    const auth = await fetch(supabaseUrl + "/auth/v1/user", {
+      headers: { "Authorization": authorization, "apikey": apiKey },
+      signal: AbortSignal.timeout(5000),
+    });
+    if (!auth.ok) return json({ error: "UNAUTHENTICATED" }, 401);
+    const user = await auth.json();
+    if (typeof user.id !== "string" || user.is_anonymous === true) {
+      return json({ error: "UNAUTHENTICATED" }, 401);
+    }
+  } catch (_) {
+    return json({ error: "AUTH_UNAVAILABLE" }, 503);
+  }
+
+  let body: unknown;
+  try { body = await request.json(); }
+  catch (_) { return json({ error: "INVALID_JSON" }, 400); }
+
+  const payload = body as Record<string, unknown> | null;
+  const ids = payload?.trackIds;
+  if (!Array.isArray(ids) || ids.length < 1 || ids.length > 3
+      || ids.some((id) => typeof id !== "string" || !allowed.test(id))
+      || new Set(ids).size !== ids.length) {
+    return json({ error: "INVALID_TRACK_IDS", maximum: 3 }, 400);
+  }
+
+  // The existing edge/cache layer owns any metadata caching. We only warm it.
+  // This never calls /playback/resolve or fetches audio bytes.
+  const results = await Promise.all((ids as string[]).map(async (id) => {
+    const match = allowed.exec(id)!;
+    const endpoint = new URL(
+      "/api/v1/providers/" + encodeURIComponent(match[1])
+      + "/tracks/" + encodeURIComponent(match[2]), apiOrigin,
+    );
+    try {
+      const upstream = await fetch(endpoint, {
+        headers: { "Accept": "application/json" },
+        signal: AbortSignal.timeout(4500),
+      });
+      return { trackId: id, cached: upstream.ok };
+    } catch (_) {
+      return { trackId: id, cached: false };
+    }
+  }));
+  return json({ kind: "metadata_prefetch", results });
+});
