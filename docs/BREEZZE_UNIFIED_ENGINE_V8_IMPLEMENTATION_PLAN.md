## V8 online-only media directive — 28 November 2026 (supersedes hosted-audio requirement)

**Owner decision (updated): Breezze should fetch audio and video live from online services, permit recording-by-recording device downloads where authorized, and require NO Breezze-owned media catalog or R2 media storage.** This is a media-delivery change, not deletion of the listener's Library tab, playlists, follows, account metadata, recommendations, or the existing one-player UI. Supersedes older V8 statements that private R2 audio ingestion and offline/download acceptance are mandatory prerequisites to online playback. Historical V8 source/CI evidence stays recorded, but must not be interpreted as today's product requirement.

### Online-only product contract
- **Primary playback source: provider-hosted stream on demand.** Search multiple real catalog sources; backend matches recording identity (ISRC when genuinely supported), confirms that a particular song is full-length streamable in the listener's territory and that Breezze's in-app use is permitted, and requests a short-lived authorized session. Pass approved HTTPS MP3/AAC/FLAC/HLS audio to the sole Flutter player, or preserve the provider's own sanctioned player where raw audio cannot be delivered.
- **Zero owned music files:** no required song download/upload, proprietary audio master library, R2 audio bucket, FFmpeg ingester, six-tier transcoding pipeline, permanent per-song media cache, or Breezze-hosted audio CDN. A constrained non-persistent streaming relay may pass through authorized bytes with 200/206/HEAD, stream backpressure, per-user authorization and log redaction; it must not save media payloads, pass upstream secrets to Flutter, or impersonate users.
- **Separate listener Library:** keep saved songs/playlists/follows/queue/history as minimal account-scoped metadata in the existing Supabase/Prisma/Drift architecture. This is not a stored music catalog or collection of sound recordings. Continue four tabs Home, New, Library, Search.
- **Online-first with allowed local downloads (new owner directive).** BREEZZE_MEDIA_MODE=online_only disables only the **legacy R2 audio resolver and R2 download/ingest grants**; it must not disable independent, provider-authorized device downloading. /providers/open-media/commons/resolve can return separate original provider-hosted streamUrl and downloadUrl after reviewing the upstream CC license. Flutter saves directly into listener-owned device folders with license/source attribution, no Breezze-owned server media storage. Pre-existing R2 offline leases are still blocked in this mode. Never imply any provider supports downloads unless its specific grant says so.
- **Provider scope:** Spotify/Deezer discovery remains metadata/previews only unless an approved in-app full-stream entitlement is established. YouTube Music metadata and visible official embedded YouTube videos stay separate; no audio-only extraction or unauthorized background plays. Apple Music MusicKit can stream for signed-in paying Apple Music subscribers within its permitted player; this is *not* universal free commercial access. SoundCloud's published API terms prohibit unlicensed aggregation into an alternative on-demand service; do not add it as a general fallback absent written authorization. Unofficial APIs can be tested in isolation for genuinely permitted sources but may not bypass protection or fabricate permission. **Never use Audius.**
- **OpenSubsonic is optional transport, not a required external music library:** Draft PR #93 demonstrates one rights-scoped remote-hosting adapter but no actual licensed provider/media. If no provider is connected and approved, full-song playback is unavailable; the UI must not pretend otherwise. Evaluate alternative documented online provider integrations with the same contract, without creating duplicate players.

### On-demand no-storage audio AND video: first real public-licensed provider (draft)

- Wikimedia Commons official MediaWiki API: authenticated **GET /api/v1/providers/open-media/commons/search?q=...&kind=audio|video** returns only files whose API-reported LicenseUrl matches a conservative Creative Commons allowlist (CC0, CC BY, CC BY-SA), whose reported MIME is audio or video, and whose returned media URL is from upload.wikimedia.org. All potentially ambiguous/restricted/no-license files are excluded. **This license metadata is user-supplied and remains subject to verification; it is not blanket rights assurance.**
- **GET /api/v1/providers/open-media/commons/resolve?title=File:...&kind=audio|video** rechecks the current published rights before presenting streamUrl and device downloadUrl. Source page, author, license, size and exact MIME are included for attribution and integrity validation.
- Flutter Search has an explicit **Open media · Play & download** subview. Audio uses the one global Flutter player; video uses the existing video_player dependency; file downloads stream original provider bytes directly to an owner-scoped device directory and preserve license metadata. **No new hosted server recordings or API media-relay cache.**
- Both backend and client are **draft** and unverified in live Commons traffic, Dart/Flutter builds, source encoding/codec support, device offline playback and Commons rate-limit approvals. The integration is not yet production-ready. Do not describe Commons as a large commercial music/video catalog; it is open content, not the Spotify/YouTube commercial archive. Official music-video embeds and mainstream provider-rights integrations remain separate.
- Jamendo offers artist-selected audio download URLs but its standard API terms restrict offline-app design. Do not represent Jamendo tracks as generally offline-eligible without an appropriate contract. YouTube and Spotify extraction and unauthorized downloading remain prohibited; no Audius.

### Mainstream full-catalog source candidates — rights-aware online playback + offline

The Wikimedia Commons adapter is the first **open-licensed technical proof**, not the solution for mainstream label catalogs. Use commercial *media delivery by another provider* rather than storing a Breezze song master:

1. **MassiveMusic / 7digital:** Published subscription API contracts document full-track online streaming (`/stream/subscription`) and subscriber/device-qualified encrypted offline media (`/offline/subscription` and HLS `/offline/subscription.m3u8`). The provider hosts encoded recordings; downloads are kept on approved listener devices with entitlement checks, expiry and offline-play reporting. This is the closest verified API **shape**, not evidence of Breezze access or rights. Obtain an agreement, commercial credentials, territory catalog list and offline/DRM implementation details before integrating. References: https://docs.massivemusic.com/reference/stream-to-subscriber-offline and https://docs.massivemusic.com/reference/stream-to-subscriber-offline-hls and https://docs.massivemusic.com/reference/stream-to-subscriber
2. **Tuned Global:** DSP-style music API and partner-operated catalog/streaming stack with online and offline use cases, subject to the negotiated scope and country rights. References: https://docs.tunedglobal.com/use-cases-1/build-a-streaming-service and https://www.tunedglobal.com/streaming-services/streaming-music-api-for-apps
3. **Other approved providers:** Only integrate sources that positively establish full-audio or full-video rights and permitted client downloads per recording, product, region and device. Provider SDK embedding and protected offline DRM are supported as separate, truthful playback modes; do not represent an embedded app player as unrestricted native audio or decrypt the vendor's protected streams.

**Implementation tasks:** add typed B2B provider adapter behind capability negotiation, backend entitlement and country checks, separate online source and short-lived offline license, provider-configured HLS/native decoder, account-bound encrypted device cache where required, playback reporting, license renewal and revocation. Do **not** configure a proxy that leaks raw vendor tokens or DRM media. Audio/video downloads remain opt-in per source. No license/access contract or live commercial full-song byte verification presently exists; PR #93 remains draft. The product cannot reach a commercial-catalog 100% gate until one or more providers actually provision the catalog and rights.

### Required acceptance for online-only music
1. Real online search returns song, artist and supported provider with accurate full/preview/unavailable status. Never show a 30-second preview as the full recording or silently switch to a remix.
2. Provider API actually returns non-expired playable **full-length** audio under an in-app entitlement; verify with sustained byte delivery, codec/probe/duration, HTTP 200/206 seek, pause/resume and no credential leaks. No dependency on Breezze R2 object inventory.
3. Test just_audio and audio_service on actual Android/iOS emulators and native devices, as well as macOS/Linux/Windows/web, covering foreground/background media controls, queue/next/previous, interruption restoration and error/fallback behavior. Provider-specific SDK/webview players must be visibly distinguished where they cannot be native sources.
4. Verify **zero server-side** retention of full-track music or video by Breezze; allow explicit downloaded files **on the listener's device only**, with original provider/source/creator/license and user-scoped storage. Validate original byte length, MIME, storage limits, cancellation/account changes, app restart and local playback. Online playback requires connectivity; downloaded eligible files do not.
5. Pass exact-head CI, vulnerability and secret gates, accessibility, signing and distribution; release/deploy/merge freeze continues until proof and owner approval.

**Implementation checkpoint (draft only):** PR #93 adds a disabled-by-default provider-hosted OpenSubsonic source, a disabled-by-default CC-licensed Wikimedia Commons audio/video discovery and direct device-download path (BREEZZE_OPEN_MEDIA_ENABLED=true), and a guarded BREEZZE_MEDIA_MODE=online_only server switch. Production mode remains unchanged until safe release. Provider availability, rights, approval and native E2E are NOT VERIFIED; this section is a target contract, not a 100% completion declaration.

### Consolidated engineering decisions retained in V8

- Retain the existing Flutter monorepo (`apps/mobile`) with Riverpod and the shared `design_system`, `api_client`, and `audio_contracts` packages. No second app, UI toolkit, client-wide theme or audio controller.
- Use one NestJS/Prisma API; Supabase Auth/Postgres with schema/RLS boundaries; Cloudflare API and media Workers with private R2; Drift/SQLite and a per-account outbox on devices. Do not add redundant Isar/Hive databases or duplicate cloud gateways.
- Four tabs are **Home / New / Library / Search** (New replaces the older Browse label). Retain one persistent global player, queue, Now Playing, and adaptive desktop sidebar/phone tab bar.
- Catalog APIs are for discovery and legally available previews only. Spotify/Deezer/YouTube Music metadata is never a full-track distribution or offline entitlement. Full native audio and downloads require independently authorized licensed assets, territory/time-granted sessions and actual verified delivery bytes.
- Preserve legacy account IDs/data until an explicitly tested migration; validate cross-account isolation, Google/Apple native sign-in configuration, and rights/security/account-transition tests before changing production auth.
- Keep the absolute release, production deployment, downloadable source/artifact and store-publication freeze until every required V8 verification gate and explicit owner approval. Historical CI or implementation source alone is not proof of completion.

## Product contract (single source of truth)
- **Four top-level tabs in order:** **Home**, **New** (formerly Browse), **Library**, **Search**; no fifth Radio/Downloads/Settings tab.
- **Home:** listener-scoped history, favorites, follows, personalized shelves with honest source metadata. Do not label algorithmic shelves or charts as official without a real dataset.
- **New:** verified new releases, charts if licensed/attributed data exists, genre and mood discovery, music-video entry points.
- **Library:** saved songs, playlists, albums, followed artists, offline media, and download progress/failure recovery.
- **Search:** songs, artists, lyrics, and genre hubs; keep unplayable catalog results distinguishable from playable recordings.
- **Premium listening UX:** one mini-player, one Now Playing, consistent artwork, animations respecting Reduce Motion, Dynamic Type/text scaling, VoiceOver/TalkBack labels, keyboard/desktop navigation, and a stable back stack.
- **AutoMix:** online *optional* beat-matched transitions for **two authorized, simultaneously playable** audio streams; no provider extraction. A planning-only algorithm is **not** a mixed-audio engine. Fall back to gapless/normal transition if analysis, rights, decoder, or CPU budget is unavailable.
- **Offline:** rights-granted full tracks only. Encrypted, per-user app-private media with lease expiry/revocation, network/Wi-Fi gating, pause/resume/cancel, durable jobs, hash/integrity evidence, user-visible reason and retry; no YouTube/Spotify/Deezer metadata downloads.
- **Calls:** automatically pause during phone/exclusive audio interruptions, *resume after focus returns only if that same interruption paused active playback*, no intervening user pause/stop/track change, and current grant still authorized; **never** auto-resume after unplug/Bluetooth route removal.
- **Credentials:** client only receives public Supabase publishable key; server credentials remain in deployment secret stores or encrypted Supabase Vault with restricted SQL access. Add to `.gitignore`, never copy secrets into Git/issue/CI artifacts/logs or plaintext `public` tables. Inventory names and references, not values. Any exposed key must be revoked/rotated.

## Architecture (keep existing working services)
```
Flutter BreezzeShell (Home/New/Library/Search)
  -> global PlayerController + queue + OS audio_service
  -> PlaybackResolver / session + heartbeat (NestJS API on Railway)
  -> rights decisions (Prisma + Supabase Postgres)
  -> signed media worker (Cloudflare Workers + private R2)
  -> just_audio / ExoPlayer / AVFoundation / media_kit
```
Spotify/Deezer/MusicBrainz = discovery/metadata/previews only where licensed. YouTube Music = officially supported visible video playback. Only verified licensed Breezze assets or an actual authorized partner playback API can supply full-track native bytes. Secrets must **never** flow into the Flutter binary.
